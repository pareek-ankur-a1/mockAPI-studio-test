## Startup

```
src/index.js
  └── import createApp() from app.js
  └── connectDB()            ← connects to MongoDB Atlas
  └── http.createServer(app)
  └── server.listen(PORT)
  └── SIGTERM / SIGINT → graceful shutdown (10s force-exit)
```

`app.js` is a **factory function** (not a singleton) — it creates and configures the Express app but does NOT call `listen()`. This separation makes it importable in tests without binding to a port.

## Middleware Pipeline

Every request passes through this stack in order:

```
CORS headers (dashboard: CLIENT_URL only)
    │
Body parsing (express.json, express.urlencoded, limit: 1mb)
    │
Dev request logger (NODE_ENV=development only)
    │
Health check GET /health ──────────────────────────── returns 200 immediately
    │
Route dispatch
    ├── /api/auth/*     → authRouter          (no JWT required)
    ├── /api/mock/*     → cors(*) → mockRouter (open CORS, rate limited)
    └── /api/internal/* → verifyJWT
                          → requireVerified
                          → internalRouter
    │
404 handler (unmatched routes)
    │
Global error handler (Mongoose 11000 → 409, ValidationError → 400, else 500)
```

### CORS — two policies

| Route prefix | Allowed origins | Why |
|-------------|-----------------|-----|
| `/api/auth/*` | `CLIENT_URL` (from env) | Only the dashboard should register/login |
| `/api/internal/*` | `CLIENT_URL` | Only the dashboard manages projects |
| `/api/mock/*` | `*` (everyone) | Users call these from their own apps on any domain |

The mock router applies its **own** `cors({ origin: '*' })` internally — the app-level CORS does not affect it.

## Database Models

### User

```
users collection
┌──────────────┬──────────────────────────────────────────┐
│ Field        │ Notes                                    │
├──────────────┼──────────────────────────────────────────┤
│ name         │ String, required, max 100 chars          │
│ email        │ String, unique, lowercase, regex-validated│
│ passwordHash │ String, select: false (bcrypt, 12 rounds)│
│ isVerified   │ Boolean, default false                   │
│ otpHash      │ String, select: false (SHA-256 of OTP)   │
│ otpExpiresAt │ Date,   select: false (now + 10 min)     │
│ otpAttempts  │ Number, select: false (max 5)            │
│ createdAt    │ auto (timestamps: true)                  │
│ updatedAt    │ auto                                     │
└──────────────┴──────────────────────────────────────────┘
```

`select: false` means these fields are **never returned** in queries unless you explicitly call `.select('+fieldName')`. This prevents passwords and OTP hashes from leaking into API responses by accident.

### Project

```
projects collection
┌─────────────┬──────────────────────────────────────────────┐
│ Field       │ Notes                                        │
├─────────────┼──────────────────────────────────────────────┤
│ name        │ String, required                             │
│ description │ String, optional                             │
│ prefix      │ String, unique — e.g. "proj_8f72k"           │
│             │ Auto-generated by pre-save hook.             │
│             │ 36^5 ≈ 60M possible values.                  │
│             │ Immutable after creation.                    │
│ owner       │ ObjectId → users._id                         │
└─────────────┴──────────────────────────────────────────────┘
```

The `prefix` is the public-facing identifier in all mock URLs: `/api/mock/{prefix}/{resource}`.

### Resource

```
resources collection
┌──────────────────┬─────────────────────────────────────────────┐
│ Field            │ Notes                                       │
├──────────────────┼─────────────────────────────────────────────┤
│ projectId        │ ObjectId → projects._id                     │
│ resourceName     │ String, URL-safe (regex: /^[a-z0-9-]+$/)    │
│ schemaDefinition │ Schema.Types.Mixed — stores the JSON Schema │
│ description      │ String, optional                            │
└──────────────────┴─────────────────────────────────────────────┘
Compound unique index: { projectId: 1, resourceName: 1 }
→ Same resource name allowed across different projects.
→ Duplicate name within the same project → 409 Conflict.
```

### MockData

```
mockdata collection
┌────────────┬─────────────────────────────────────────────────┐
│ Field      │ Notes                                           │
├────────────┼─────────────────────────────────────────────────┤
│ resourceId │ ObjectId → resources._id                        │
│ data       │ Schema.Types.Mixed — stores any JSON payload    │
│ isSeeded   │ Boolean — true if created by the Faker seeder   │
│ createdAt  │ auto                                            │
└────────────┴─────────────────────────────────────────────────┘
Compound index: { resourceId: 1, createdAt: -1 }
→ Efficient sorted reads within a resource.
```

`Schema.Types.Mixed` is intentional — it stores arbitrary JSON without enforcing any MongoDB schema on the data field itself. The JSON Schema validation is handled at the application layer (Ajv) before writing, not at the DB layer.

> **Important:** When updating a Mixed field, always call `doc.markModified('data')` before `doc.save()`, otherwise Mongoose won't detect the change and won't write it to MongoDB.

## Auth Routes

Base path: `/api/auth`

All responses follow `{ success: boolean, message: string, ...data }`.

---

### `POST /api/auth/register`

Creates a new user account, sends OTP to their email, returns a JWT.

**Request body:**
```json
{
  "name": "Riya Sharma",
  "email": "riya@example.com",
  "password": "mypassword123"
}
```

**Validations:**
- All fields required
- Password ≥ 8 characters
- Email must be unique (409 if duplicate)

**Response `201`:**
```json
{
  "success": true,
  "message": "Account created! A 6-digit verification code has been sent to riya@example.com.",
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user": {
    "_id": "6ab...",
    "name": "Riya Sharma",
    "email": "riya@example.com",
    "isVerified": false,
    "createdAt": "2026-09-25T..."
  }
}
```

The returned token has `isVerified: false` in its payload. The frontend should redirect to `/verify-email`.

---

### `POST /api/auth/login`

**Request body:**
```json
{ "email": "riya@example.com", "password": "mypassword123" }
```

**Response `200`:**
```json
{
  "success": true,
  "token": "eyJ...",
  "user": { "_id": "...", "name": "Riya", "email": "...", "isVerified": true }
}
```

**Security:** Returns identical `"Invalid email or password."` for both wrong email AND wrong password — prevents user enumeration.

---

### `POST /api/auth/verify-email` *(JWT required)*

**Headers:** `Authorization: Bearer <token>`

**Request body:**
```json
{ "otp": "847293" }
```

**Response `200` (success):**
```json
{
  "success": true,
  "message": "Email verified successfully!",
  "token": "eyJ... (NEW token with isVerified: true)",
  "user": { "isVerified": true, ... }
}
```

The client must **replace** the old token with the new one returned here.

**Response `400` (wrong OTP):**
```json
{ "success": false, "code": "OTP_INVALID", "message": "Incorrect code. 3 attempts remaining." }
```

**Response `400` (expired):**
```json
{ "success": false, "code": "OTP_EXPIRED", "message": "This code has expired. Please request a new one." }
```

**Response `429` (locked):**
```json
{ "success": false, "code": "OTP_LOCKED", "message": "Too many wrong attempts. Please request a new verification code." }
```

---

### `POST /api/auth/resend-otp` *(JWT required)*

Generates a fresh OTP and emails it. Resets the attempt counter.

**Rate limit:** 3 requests per 15 minutes per IP.

**Response `200`:**
```json
{ "success": true, "message": "A new verification code has been sent to riya@example.com." }
```

---

### `GET /api/auth/me` *(JWT required)*

Returns the current user's live profile from DB (not just the token payload).

**Response `200`:**
```json
{ "success": true, "user": { "_id": "...", "name": "...", "email": "...", "isVerified": true } }
```

Used by the frontend on page load to validate a stored token without making the user log in again.

## Internal Routes

Base path: `/api/internal`

**All routes require:**
1. `Authorization: Bearer <token>` header
2. The user's email must be verified (`isVerified: true` in token)

All project/resource queries are automatically **scoped to the authenticated user's ID** — you cannot see or modify another user's data.

---

### Projects

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/projects` | List all your projects |
| `POST` | `/projects` | Create a project |
| `GET` | `/projects/:projectId` | Get one project |
| `DELETE` | `/projects/:projectId` | Delete + cascade (resources + mockdata) |

**POST /projects body:**
```json
{ "name": "Movie Booking App", "description": "Optional description" }
```

**POST /projects response `201`:**
```json
{
  "success": true,
  "message": "Project \"Movie Booking App\" created with prefix \"proj_m4x9z\".",
  "data": { "_id": "...", "name": "Movie Booking App", "prefix": "proj_m4x9z", "owner": "...", ... }
}
```

---

### Resources

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/projects/:projectId/resources` | List resources (includes record counts) |
| `POST` | `/projects/:projectId/resources` | Create resource + validate JSON Schema |
| `PUT` | `/resources/:resourceId` | Update schema (invalidates Ajv cache) |
| `DELETE` | `/resources/:resourceId` | Delete + cascade MockData |

**POST /projects/:id/resources body:**
```json
{
  "resourceName": "movies",
  "schemaDefinition": {
    "type": "object",
    "properties": {
      "title": { "type": "string" },
      "genre": { "type": "string", "enum": ["Action", "Drama"] }
    },
    "required": ["title"]
  },
  "description": "All currently showing movies"
}
```

The `schemaDefinition` is validated against the JSON Schema meta-schema using `ajv.validateSchema()` before saving. A malformed schema (e.g., invalid `$ref`, wrong type keyword) is rejected with `400` before it ever reaches the database.

---

### Seeding

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/seed` | Bulk-insert fake records using Faker.js |

**POST /seed body:**
```json
{ "resourceId": "6ab5...", "count": 50 }
```

- `count` max: **500** (hard cap to prevent DB flooding)
- Uses `insertMany` with `ordered: false` for bulk efficiency
- All seeded records are tagged with `isSeeded: true`

**Response `201`:**
```json
{
  "success": true,
  "stats": { "requested": 50, "inserted": 50, "elapsedMs": 312 },
  "preview": [ { "title": "...", "genre": "..." }, ... ]
}
```

## Mock Engine Routes

Base path: `/api/mock`

**CORS:** `*` (open to all origins — no restrictions)

**No authentication required** — these are the public mock endpoints your app calls.

---

### `GET /api/mock/:prefix/:resource`

Returns paginated records for a resource.

**Query params:**
| Param | Default | Description |
|-------|---------|-------------|
| `limit` | 100 | Max records per page |
| `page` | 1 | Page number |
| `seeded` | (all) | `true` = only seeded, `false` = only real |

**Response `200`:**
```json
{
  "success": true,
  "meta": { "total": 50, "page": 1, "limit": 20, "totalPages": 3 },
  "data": [
    { "_id": "6ab5...", "title": "Interstellar", "genre": "Sci-Fi", "_isSeeded": false }
  ]
}
```

---

### `GET /api/mock/:prefix/:resource/:id`

Returns a single record.

---

### `POST /api/mock/:prefix/:resource`

Creates a record after validating the body against the resource's JSON Schema.

**Rate limit:** 60 writes/min per IP.

**Request body:** Must match the resource's stored JSON Schema exactly.

**Response `201`:**
```json
{ "success": true, "data": { "_id": "...", ...yourFields } }
```

**Response `400` (invalid body):**
```json
{
  "success": false,
  "message": "Request body failed schema validation.",
  "errors": [
    { "field": "/price", "message": "must be >= 0" },
    { "field": "/category", "message": "must be equal to one of the allowed values" }
  ]
}
```

---

### `PUT /api/mock/:prefix/:resource/:id`

Full replacement of a record's data. Same Ajv validation as POST.

---

### `DELETE /api/mock/:prefix/:resource/:id`

Deletes a single record (scoped to that resource — cannot delete records from other resources by guessing IDs).

---

### `DELETE /api/mock/:prefix/:resource`

Bulk delete all records for a resource.

**Query params:**
- `?seeded=true` → delete only Faker-seeded records
- `?seeded=false` → delete only real (user-POSTed) records
- (no param) → delete all

## Ajv Validation & Caching

```
First request to POST /api/mock/proj_abc/products:
  1. validateSchema middleware resolves Project + Resource from DB
  2. ajv.getSchema(resource._id) → undefined (cache miss)
  3. ajv.compile(schemaDefinition) → compiled ValidateFunction
  4. Compiled function stored in Ajv's internal cache keyed by resource._id

Subsequent requests to the same endpoint:
  1. ajv.getSchema(resource._id) → returns cached ValidateFunction (O(1))
  2. Run validate(req.body) → instant, no recompilation

Schema update via PUT /api/internal/resources/:id:
  1. ajv.removeSchema(resourceId) → evict from cache
  2. Next mock request recompiles from new schemaDefinition

Schema update handled by another server instance:
  1. Each POST/PUT reads the current schema from MongoDB
  2. Compare it to the locally compiled validator's schema
  3. Evict and recompile if it changed
```

Ajv is configured with:
- `allErrors: true` — collect ALL errors, not just the first one
- `coerceTypes: false` — strict type checking (string `"5"` ≠ integer `5`)
- `useDefaults: true` — fill in `default` values from schema
- `ajv-formats` registered — supports `email`, `uri`, `date`, `date-time`, `uuid`, `ipv4` formats

## Faker Seeding

The `fakerMapper.js` utility maps a JSON Schema definition to Faker.js methods.

Priority order:
1. **`enum`** → `faker.helpers.arrayElement(enumValues)`
2. **`const`** → exact value
3. **`anyOf` / `oneOf`** → uses the first branch
4. **Property name hints** (40+ patterns) — e.g.:
   - `email` / `mail` → `faker.internet.email()`
   - `firstName` / `name` → `faker.person.firstName()`
   - `price` / `cost` → `faker.commerce.price()`
   - `avatar` / `photo` → `faker.image.avatar()`
   - `phone` / `mobile` → `faker.phone.number()`
   - `city` → `faker.location.city()`
   - `createdAt` / `date` → `faker.date.recent().toISOString()`
5. **JSON Schema `format`** — `email`, `uri`, `date-time`, `uuid`, etc.
6. **JSON Schema `type`** — `string`, `number`, `integer`, `boolean`, `array`, `object`
7. **Fallback** → `faker.lorem.word()`

## OTP & Email Flow

```
utils/otpHelper.js:
  generateOTP()    → crypto.randomInt(100000, 1000000).toString()  // 6 digits, cryptographically random
  hashOTP(otp)     → crypto.createHash('sha256').update(otp).digest('hex')
  otpExpiresAt()   → new Date(Date.now() + 10 * 60 * 1000)
  verifyOTP(user, submitted):
    → 'missing'   if no otpHash stored
    → 'expired'   if new Date() > otpExpiresAt
    → 'locked'    if otpAttempts >= 5
    → 'invalid'   if hashOTP(submitted) !== otpHash
    → 'ok'        otherwise

utils/emailService.js:
  sendOtpEmail(to, name, otp)
    → reads BREVO_API_KEY and verified EMAIL_FROM sender
    → sends branded HTML and text through the Brevo HTTPS API
    → uses a 10-second timeout and reports delivery errors without logging secrets
    → registration keeps its token and reports emailSent: false if sending fails
    → resend returns 503 on delivery failure
```

## Error Handling

The global error handler in `app.js` catches all errors passed via `next(err)`:

| Error Type | HTTP Status | Trigger |
|-----------|-------------|---------|
| Mongoose duplicate key (code 11000) | 409 | Duplicate email, duplicate prefix |
| Mongoose ValidationError | 400 | Schema constraint violated |
| Custom `err.statusCode` | as set | e.g. `requireOwnedProject` throws 404 |
| Any other error | 500 | Unexpected failures |

In `development` mode the error response includes `stack` for debugging. In production it's omitted.

## Rate Limiting

| Limiter | Applied to | Max | Window |
|---------|-----------|-----|--------|
| `mockReadLimiter` | GET /api/mock/* | 100 | 1 minute |
| `mockWriteLimiter` | POST/PUT/DELETE /api/mock/* | 60 | 1 minute |
| `otpVerifyLimiter` | POST /api/auth/verify-email | 10 | 15 minutes |
| `otpResendLimiter` | POST /api/auth/resend-otp | 3 | 15 minutes |
| `loginLimiter` | POST /api/auth/login | 20 | 15 minutes |
| `registerLimiter` | POST /api/auth/register | 5 | 15 minutes |
| `seedLimiter` | POST /api/internal/seed | 5 per user | 1 minute |

All policies use `rate-limit-redis` when `REDIS_URL` is configured, with separate
key prefixes and fixed windows. Redis is required in production. Without a URL
in development, `express-rate-limit` uses its memory store. All policies are per
IP except seeding, which uses the authenticated user's ID. A Redis store failure
returns `503`; exhausted limits return `429` with `Retry-After`.

## Redis response cache

`src/services/mockCache.js` caches successful mock list and detail GET responses
for `MOCK_CACHE_TTL_SECONDS` (default 30). Keys include the project and request
variant. The controllers invalidate the whole project's generation after mock
writes, seeding (including partial inserts), schema/resource updates, and cascade
deletes. Lua guards cache fills against concurrent invalidation; TTLs clean up
old generations. Responses over 1 MiB and errors are not cached.

`X-Cache: HIT|MISS|BYPASS` reports cache usage. Rate limits run before cache reads,
so hits still consume quota. Cache reads fall back to MongoDB on error. Failed
invalidation returns `503` and warns that the write may already have committed.

See the [root README](../README.md#redis-caching-and-rate-limiting) for Redis Cloud
configuration, environment variables, failure behavior, and tests. `npm test`
uses test doubles by default; set `REDIS_TEST_URL` for the additional live test.
